**Context:** Implementing Mermaid diagrams for docs/02 (phase-gate pipeline) and docs/04 (worked timeline gantt), then generating an OpenArt AI prompt for the Executive Summary leadership exhibit.

**Key Exchanges:**

- Q: Does a Mermaid fence render correctly in both GitHub Pages (Jekyll/Rouge) and github.com's native renderer?
  A: Yes, but with constraints. Pages uses assets/js/diagrams.js to swap Rouge-emitted fences for `<figure>` elements with Mermaid 11.16.1 themed via CSS tokens. github.com renders the same fence natively in a sandboxed iframe. Colors must be hard-coded in `classDef` blocks because the site stylesheet never loads on github.com — confirmed via DOM inspection of the iframe.

- Q: Does Mermaid's `useMaxWidth` prevent gantt charts from shrinking on mobile?
  A: No. Mermaid auto-fits gantt charts to the live container width regardless of `useMaxWidth`. The fix is `gantt.useWidth: 672` to pin to a fixed pixel width, letting the scroll container handle overflow instead of the chart shrinking.

- Q: Why did mobile overflow scroll not work even after pinning width?
  A: `pre.mermaid` is a block element that fills its parent's width rather than sizing to its wider child SVG, so overflow never reached `figure.diagram`'s scroll container. Fix: `width: max-content` on `pre.mermaid`.

**Lessons Learned:**

- Mermaid `wrappingWidth` (default 200px) silently re-wraps node labels, ignoring author-inserted `<br/>` tags. Edge labels ignore `wrappingWidth` entirely — explicit breaks must be written into the source.
- Mermaid gantt section titles that are full sentences collide with task rows; short bare phase names are required.
- Double-digit tick labels overlap at 2-week intervals — 4-week interval with bare numbers (no "Wk " prefix) is the practical fix.
- Mobile gantt bugs stack: auto-fit → pin with useWidth → overflow blocked by pre box model → fix with max-content. All three root causes are independent and each must be fixed. Static single-viewport screenshots miss mobile entirely.
- Getting verified against the deployed page (not local guesses) at desktop light/dark AND mobile is necessary — a pattern that will apply to all future diagrams.
